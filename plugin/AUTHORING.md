# Авторство пресета по одному брифу

Плагин даёт автору три вещи: скиллы `bughunter:bughunter-preset-guide` и
`bughunter:bughunter-core-contract`, рабочий шаблон CLI-пресета с фикстурой и бриф, который
превращается в одно задание агенту. Это не one-shot на минуту: агент проходит гайд, адаптирует
шаблон, пишет фикстуру и прогоняет детерминированную приёмку.

## 1. Найдите установленный плагин

```sh
qwen plugins list --json
```

Возьмите `installPath` (например, `~/.qwen/plugins/cache/local/bughunter/0.1.0`). Шаблон лежит в
`<installPath>/template/cli-preset`, core — в `<installPath>/server/core`.

## 2. Заполните бриф

Шаблон брифа — `<installPath>/template/authoring-brief.md`. В нём домен, целевое приложение,
фикстура, засеянные дефекты, симптомы, формы `check` и критерий приёмки.

## 3. Одно задание агенту

Скопируйте рабочий каталог и передайте агенту бриф целиком:

```sh
mkdir -p ~/bh-authoring
cp -R <installPath>/template/cli-preset ~/bh-authoring/my-preset
cd ~/bh-authoring && git init -q -b main
```

`.git` обязателен: core ищет корень проекта, а экспорт отказывается класть тест в проект без него.

```text
Прочитай ~/bh-authoring/brief.md. Используй Skill bughunter:bughunter-preset-guide и
bughunter:bughunter-core-contract. Шаблон: ~/bh-authoring/my-preset. Core:
<installPath>/server/core. Собери пресет под домен из брифа, замени фикстуру и тесты,
не меняя core. Прогони детерминированную приёмку и верни отчёт: найденные дефекты,
ложные подтверждения, пути red-тестов и результаты их независимого запуска.
```

Агент работает в обычной сессии `qwen`; ему нужны `Read`, `Edit`, `Write`, `Bash` и `Skill`.
Подключение MCP-сервера Bughunter для авторства не требуется.

## 4. Сделайте пресет запускаемым отдельно

В `my-preset/preset/package.json` замените `"@bughunter/core": "*"` на путь к core из плагина:

```json
"@bughunter/core": "file:<installPath>/server/core"
```

Затем:

```sh
cd ~/bh-authoring/my-preset/preset
npm install --no-audit --no-fund
```

## 5. Детерминированная приёмка

```sh
cd ~/bh-authoring/my-preset/preset
node --test --test-concurrency=1 test/*.bhtest.ts
```

Критерии, которые агент обязан показать в отчёте:

- найдено не меньше порога из брифа (например, 3 из 4 засеянных);
- **0** подтверждённых ложных срабатываний на контрольной цели;
- на каждый подтверждённый баг экспортирован red-тест;
- каждый red-тест перепроверен **независимым** запуском, а не со слов писателя;
- `core/` не изменён ни на строку.

Шаблон — это работающий CLI-пресет с собственной фикстурой и приёмочными тестами. Его домен
(CLI) заменяется на ваш; раскладка, harness, replay, экспорт и проверка вердикта остаются
образцом.

## 6. Что проверить человеку

1. Прочитать отчёт приёмки и список засеянных дефектов.
2. Запустить экспортированные red-тесты самому.
3. Убедиться, что контрольная цель не даёт находок.
4. Проверить, что в пресете нет заглушек `PRESET_HOOK_NOT_WIRED` и `pending(`.
5. Только после этого подключать пресет как `.mcp.json` или отдельный плагин.

## Авторство общее, хосты — нет

Авторство пресета хост-нейтрально: гайд, контракт-скилл, шаблон и бриф общие для Qwen, Kimi и
Claude — сборка подставляет пути, имена инструментов и инструкции перезагрузки из host descriptor
(`plugin/hosts/<host>.mjs`). Добавление нового хоста — это **descriptor и гейты, а не правки core**:
новый `plugin/hosts/<host>.mjs`, artifact/marketplace-тесты артефакта и evidence-гейты поддержки
(`plugin/evidence/`, `plugin/support-matrix.mjs`). Core и пресеты при этом не меняются — критерий
«ноль правок core» относится и к хостам: core не правится ради хоста так же, как не правится ради
пресета. Пока гейты хоста не пройдены, хост остаётся planned/experimental и README артефакта не
заявляет полный workflow.

## Ограничения

- Авторский шаблон и скиллы не превращают приёмку в формальность: это 16 интерфейсов плюс обязательные `name` и `configSchema` — 18 полей `Preset`, как у web/node, с фикстурой и измеримым порогом.
- Один бриф — это один агентский проход, а не гарантия результата. В приёмке гайдлайнов первая
  итерация дала 0/4 из-за дефекта гайда; после правки — 3/4, 0 ложных и 4/4 red. Отчёт и повторная
  проверка обязательны.
- Шаблон и скиллы едут в установочном каталоге плагина. Центральной/npm-публикации нет; HTTPS zip и self-hosted marketplace являются отдельными release-каналами и не означают, что публичный URL уже существует.
