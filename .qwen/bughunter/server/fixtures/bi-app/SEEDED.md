# Засеянные дефекты и легальные трансформации `bi-app`

Источник правды — реестр `SEEDED` в `src/mocks/bugs.ts`; этот документ его человеческое зеркало.
Графа «чем обнаружим» честная: `oracle` означает, что **сегодня** Bughunter такой баг не находит —
для него нужен оракул сверки «ответ API ↔ проекция в UI», который относится к фазе 2.

## Баги данных (6)

| id | экран | виджет | ожидалось | получено | чем обнаружим |
| --- | --- | --- | --- | --- | --- |
| D1 | `/dashboard/:id` | table | Итого равен сумме строк | Итого больше суммы строк на 10 (`TOTAL_OFFSET`) | oracle:ответ |
| D2 | `/dashboard/:id` | kpi | Средний чек 1 234,57 (half-up) | 1 234,56 — усечение вместо округления (`truncateToCents`) | oracle:проекция |
| D3 | `/dashboard/:id` | — | Обновлён: 01.03.2026 (Europe/Moscow) | 28.02.2026 — форматирование в America/New_York | oracle:проекция |
| D4 | `/dashboard/:id` | line | Фильтр региона применён ко всем виджетам | Таблица фильтруется, линейный график запрашивается без региона | oracle:запрос |
| D5 | `/dashboard/:id` | table | Вторая страница продолжает первую | Строка `id 7` отдаётся повторно (`duplicateOnSecondPage`) | oracle:ответ |
| D6 | `/dashboard/:id` | kpi | Доля 52% (`paid / regionRows` = 520/1000) | 37% — знаменатель `allRows` = 1405 из того же ответа | oracle:проекция |

Три формы оракула, которые нужны фазе 2, чтобы закрыть все шесть багов:

- `oracle:ответ` — внутренняя противоречивость одного ответа API (D1: `total` против суммы `rows`;
  D5: повтор `id` между страницами). Данные для проверки есть в самом ответе.
- `oracle:проекция` — пересчёт эталона из ответа и сравнение с тем, что показано (D2: half-up от
  `kpi.avgCheck`; D3: дата из `dashboard.updatedAt` в зоне `Europe/Moscow`; D6: `paid / regionRows`).
  Поэтому значения плиток отдаёт `GET /api/dashboards/:id/widgets/kpi`, а не держит компонент:
  эталон, зашитый в рендер, оракул пересчитать не сможет и баг станет ненаходимым.
- `oracle:запрос` — сравнение URL запроса с активным фильтром (D4: запрос `widgets/line` без
  `?region=`, хотя таблица запрошена с ним). Нужен перехват сети, он в ядре уже есть.

Как увидеть: открыть `/dashboard/1`, прочитать проекции через `window.__BHProfile.extract('table')`,
`extract('line')` и плитки `kpi-avg`, `kpi-share`, `dashboard-updated`. Для D5 сначала нажать
`Показать ещё` (`data-testid="table-more"`), для D4 — сменить `filter-region`.

## Легальные трансформации (4) — приманка для ложных срабатываний

| id | экран | значение | почему это не баг |
| --- | --- | --- | --- |
| L1 | `/clean` | `1,2K` вместо 1234 | общепринятое сокращение порядка |
| L2 | `/clean` | `1 234,57` вместо 1234.5678 | локальный формат ru-RU: разделитель тысяч и запятая |
| L3 | `/clean` | `01.03.2026` для `2026-03-01T09:00:00+03:00` | корректное представление в локальной зоне |
| L4 | `/clean` | `2 400,00` для суммы с долями копеек | округление до копеек по контракту |

Любой оракул, который объявит эти значения расхождением, даёт ложное срабатывание: именно на них
калибруется порог Y из §5.4 дизайн-дока.

## Баги не про данные (3)

| id | экран | ожидалось | получено | чем обнаружим |
| --- | --- | --- | --- | --- |
| N1 | `/settings` | Экспорт CSV сообщает об отсутствии данных | Необработанное исключение при клике `export-csv` | signal (`pageerror`) |
| N2 | `/dashboard/:id` | Применяется ответ актуального фильтра | Быстрая смена фильтра применяет устаревший ответ | signal (`console.error` с префиксом `RACE:`), воспроизводится в сценарии `latency` |
| N3 | `/wizard` | Повторная отправка отчёта заблокирована | Два клика по `wizard-save` создают два отчёта | none — нарушение кратности не оставляет сигнала |

N3 — намеренная демонстрация границы: такой баг находится только проверкой кратности эффекта
(число созданных записей), которой в детекторах фазы 1 нет. Тот же класс, что и баг 3 демо-фикстуры
`buggy-app`, не подтверждённый ни в одном модельном прогоне.

## Сценарии данных

`normal` (по умолчанию), `latency` (+800 мс), `error500` (таблица дашборда отвечает 500),
`empty` (пустые списки), `big` (5000 строк таблицы). Переключение — флаг `bhScenario` в
`localStorage` плюс перезагрузка, либо `window.__BHScenario.set(<имя>)`; сброс —
`POST /__bh/reset` или запись в тот же флаг любого значения, не совпадающего с именем сценария.
