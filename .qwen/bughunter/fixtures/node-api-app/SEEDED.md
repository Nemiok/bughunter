# Засеянные дефекты `node-api-app`

Источник правды — реестр `SEEDED` в `src/bugs.js`; этот документ его человеческое зеркало.
Графа «чем обнаружим» честная: «ожидаемый пропуск» означает, что **сегодня** Bughunter такой баг
не находит, и пропуск публикуется измеренным базовым уровнем в отчёте приёмки, а не замалчивается.

Фикстура — учебное HTTP-API на голом `node:http` без рантайм-зависимостей. `vitest` нужен только
для тестов самой фикстуры и для тестов, которые экспортирует node-пресет Bughunter.

| id | эндпоинт | ожидалось | получено | чем обнаружим |
| --- | --- | --- | --- | --- |
| N1 | `POST /orders` | 400 и внятная ошибка валидации количества | 500 и стек необработанного отклонения в теле ответа | детектор: статус 5xx |
| N2 | `POST /orders` | отрицательное количество отклоняется до создания заказа | 200 и отрицательный итог заказа | check: jsonPath — `totalCents` созданного заказа |
| N3 | `GET /orders/:id` | 404 для неизвестного id | 200 и `null` в теле | check: status — 404 для несуществующего заказа |
| N4 | `POST /payments` | один ключ идемпотентности — одно списание | повторный запрос с тем же ключом списывает деньги второй раз | check: jsonPath — `balanceCents` после двух одинаковых запросов |
| N5 | `GET /orders` | итог списка называется одинаково в каждом ответе | ответы чередуют поля `totalCents` и `total` | **ожидаемый пропуск**: нужен мини-оракул схемы ответа (фаза C) |
| N6 | `POST /payments` | 502 и код сбоя шлюза без внутренних подробностей | в теле `ECONNREFUSED` и стек вызовов | детектор: аномальный токен в теле ответа |
| — | `GET /health` | всегда `{status:"ok"}`, 200, JSON | так и работает | контроль: ложных срабатываний быть не должно |

## Маршруты

| Метод и путь | Что делает |
| --- | --- |
| `GET /health` | Контрольный эндпоинт: всегда `{status:"ok"}` |
| `GET /orders` | Список заказов и итог в копейках (N5: имя поля итога чередуется) |
| `POST /orders` | Создать заказ `{qty}`; цена за единицу зависит от тарифа (N1, N2) |
| `GET /orders/:id` | Один заказ; неизвестный id отдаётся как `null` (N3) |
| `POST /payments` | Списать `{orderId, amountCents, idempotencyKey}` и авторизовать платёж в шлюзе (N4, N6) |
| `POST /__reset` | Вернуть хранилище в исходное состояние: 3 заказа, 1 платёж, баланс 10 000 копеек |

Служебные эндпоинты тестов пресета — **не засеянные баги**, в реестре `SEEDED` их нет:

| Метод и путь | Зачем |
| --- | --- |
| `GET /slow?ms=<N>` | Держит ответ N миллисекунд: проверка таймаута запроса |
| `GET /blob` | Два мегабайта не-UTF8 байтов: проверка усечения тела в снимке |

Исходное состояние: заказы `ord-1` (2 × 1200), `ord-2` (5 × 1200), `ord-3` (12 × 1000), платёж
`pay-1` с ключом `key-initial`, баланс счёта 10 000 копеек. Тарифы: до 9 штук — 1200 копеек за штуку,
10–99 — 1000, от 100 — 800.

## Как запустить

```bash
cd .qwen/bughunter/fixtures/node-api-app
npm install
node src/server.js            # stdout: listening 3000; порт — переменная PORT
npx vitest run                # тесты фикстуры: шесть дефектов присутствуют, контроль чист
```

Платёжный шлюз учебного стенда никто не поднимает: `authorizeWithGateway` стучится на
`127.0.0.1:9411` (переменная `PAYMENT_GATEWAY_PORT`) и всегда получает `ECONNREFUSED` — именно так
N6 воспроизводится детерминированно. Списание при этом уже прошло (N4), поэтому повторный запрос
тем же `idempotencyKey` уменьшает баланс второй раз.

Сброс состояния между прогонами — `POST /__reset`; node-пресет Bughunter использует его как свой
`reset` вместо браузерного `mock-endpoint`.
