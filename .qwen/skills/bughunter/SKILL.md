Разбери `$ARGUMENTS`: пустой аргумент означает `diff`; прими `diff`, `full`, `route <path>`, `screen <template>`, `sweep` или `resume <runId>`. При другом вводе остановись и кратко покажи форматы запуска. Не открывай браузер сам и ничего не коммить.

Для нового прогона вызови `bh_start_run` с выбранным scope и, для route, путём. Для возобновления вызови `bh_resume_run` с runId; продолжи только незавершённые этапы и учитывай возвращённых необработанных кандидатов, не повторяя завершённую работу. Если по состоянию этапов нужно продолжить исследование, прочти маршруты и routeStages из `run.json` этого прогона.

Области `screen` и `sweep` — детерминированные: экраны обходит сервер, а не модель. Для `sweep` сначала вызови `bh_crawl` — он построит инвентарь экранов в `state/screens.json`, где динамические сегменты сведены к шаблону (`/orders/12` и `/orders/7f3ab4c9` дают один `/orders/:id`). Затем вызови `bh_start_run` с scope `sweep` и повторяй `bh_sweep` с runId, пока в ответе не появится `done: true`; каждый вызов продолжает обход с сохранённого курсора, поэтому прерванный обход не начинается заново. Для `screen` передай шаблон из инвентаря (например `/orders/:id`) в `bh_start_run` и вызови `bh_sweep` один раз. Не расходуй модель там, где достаточно `bh_sweep`: обход проходит сотни экранов без единой сессии исследователя, а исследователь нужен для сценариев и для разбора находок.

Находки обхода (`findings` в ответе `bh_sweep` и в отчёте) — не кандидаты: `bh_triage` по findingId вернёт `FINDING_NOT_CANDIDATE`. Чтобы разобрать находку, преврати её в кандидата вызовом `bh_promote_finding` с runId, findingId, title, expected, actual и обязательным `check` — без оракула кандидата нечем воспроизвести. Дальше веди такого кандидата как обычного: `bh_reproduce`, затем reviewer, затем test-writer. Ответ `RESET_UNSUPPORTED` в находке означает, что профиль приложения не задаёт рецепт сброса данных, поэтому экран проверен в том состоянии, в котором его оставили предыдущие действия: не выдавай такой экран за проверенный начисто.

Главному агенту разрешены только `bh_start_run`, `bh_resume_run`, `bh_explore_next`, `bh_reproduce`, `bh_finish_run`, `bh_crawl`, `bh_sweep`, `bh_promote_finding`, `Read` для `run.json` и `state/screens.json` при resume и `Agent`. Запрещено напрямую вызывать `bh_open`, `bh_state`, `bh_act`, `bh_navigate`, `bh_probe`, `bh_report_candidate`, `bh_close`, `bh_triage`, `bh_export_e2e`, `bh_detect_tests`, `bh_verify_red`: они принадлежат соответствующим субагентам. В каждом сообщении модели ровно один tool/agent вызов, без batch или параллельных вызовов; дождись результата перед следующим сообщением.

Исследование идёт строгим последовательным циклом через серверную очередь задач. Повторяй: вызови `bh_explore_next` с runId. При ответе `status: 'done'` переходи к воспроизведению. При `status: 'busy'` другая задача ещё выполняется: дождись результата уже запущенного subagent и повтори `bh_explore_next`. При `status: 'task'` делегируй задачу субагенту `bh-explorer` через ровно один вызов `Agent` с `subagent_type: "bh-explorer"` и `run_in_background: false`, передав runId, `leaseId`, маршрут и персону из задачи без изменений; дождись результата, собери candidateId и повтори `bh_explore_next`. Сервер выдаёт только одну задачу за раз и не открывает сессию без действующего lease, поэтому два исследователя одновременно работать не могут: не объединяй исследователей в batch и не запускай следующего, пока предыдущий не завершён. Если исследователь вернул `FAILED: <код>` или `RETRY_LATER: EXPLORER_BUSY`, маршрут не считается проверенным: повтори `bh_explore_next` и делегируй задачу заново.

Для каждого кандидата, который ещё не воспроизведён, сам вызови `bh_reproduce`; не делегируй воспроизведение агентам. Невоспроизведённые кандидаты исключаются из дальнейшей обработки: не передавай их reviewer или test-writer. Каждого воспроизведённого кандидата без вердикта передай через отдельный foreground `Agent` (`subagent_type: "bh-reviewer"`, `run_in_background: false`), дождись вердикта и причины. Не объединяй reviewers в batch: один вызов `Agent` на сообщение и один кандидат на вызов. Передавай через foreground `Agent` (`subagent_type: "bh-test-writer"`) только подтверждённые баги, по одному с тем же правилом; отклонённые, дубли и невоспроизведённые не передавай.

При `EXPLORER_BUSY` или `RUN_INCOMPLETE` не завершай работу: вызови `bh_resume_run`, затем последовательно обработай оставшиеся задачи исследования через `bh_explore_next` и `pendingCandidates`, не повторяя завершённые этапы, и только после этого повтори finish. Вызови `bh_finish_run` с runId лишь когда необработанных кандидатов нет. Верни краткую сводку: сколько кандидатов найдено, сколько багов подтверждено, какие файлы тестов созданы и путь к отчёту. Укажи ошибки обработки, не выдавая неподтверждённых кандидатов за баги.
