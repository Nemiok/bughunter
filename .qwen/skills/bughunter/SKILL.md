Разбери `$ARGUMENTS`: пустой аргумент означает `diff`; прими `diff`, `full`, `target <path>`, `sweep`, `sweep <template>` или `resume <runId>`. При другом вводе остановись и кратко покажи форматы запуска. Не открывай сессию сам и ничего не коммить.

Оркестрация ниже от домена не зависит. Словарь инструментов пресета, его единицы исследования, области и виды `check` даёт карта пресета: вызови `Skill` с `bughunter-preset-card` до первого обращения к инструменту пресета и бери имена инструментов оттуда. Чтение карты ничего не меняет и сессию не открывает.

Для нового прогона вызови `bh_start_run` с выбранным scope и, для `target` и `sweep <template>`, целью. Для возобновления вызови `bh_resume_run` с runId; продолжи только незавершённые этапы и учитывай возвращённых необработанных кандидатов, не повторяя завершённую работу. Если по состоянию этапов нужно продолжить исследование, прочти `targets` и `targetStages` из `run.json` этого прогона.

Область `sweep` — детерминированная: цели обходит сервер, а не модель. Имена инструментов обхода, файл инвентаря и форму шаблона цели даёт карта пресета. Если карта объявляет инструмент построения инвентаря, перед полным обходом вызови его; если инвентарь статичен и builder в карте не объявлен, не выдумывай лишний вызов. Затем вызови `bh_start_run` с scope `sweep` и повторяй инструмент обхода с runId, пока в ответе не появится `done: true`; каждый вызов продолжает обход с сохранённого курсора, поэтому прерванный обход не начинается заново. Для обхода одной цели передай шаблон из инвентаря целью в `bh_start_run` с тем же scope `sweep` и вызови инструмент обхода один раз. Не расходуй модель там, где достаточно детерминированного обхода: он проходит сотни целей без единой сессии исследователя, а исследователь нужен для сценариев и для разбора находок.

Находки обхода (`findings` в ответе инструмента обхода и в отчёте) — не кандидаты: `bh_triage` по findingId вернёт `FINDING_NOT_CANDIDATE`. Чтобы разобрать находку, преврати её в кандидата вызовом `bh_promote_finding` с runId, findingId, title, expected, actual и обязательным `check` — без оракула кандидата нечем воспроизвести. Transport-schema может показывать поле optional, но это не разрешение его пропускать: без валидного check промотированного кандидата не отправляй в обычный reproduce/export-поток. Дальше веди такого кандидата как обычного: `bh_reproduce`, затем reviewer, затем test-writer. Ответ `RESET_UNSUPPORTED` означает, что пресет не имеет рецепта сброса: его владельца и поле называет карта пресета (у одних пресетов это профиль, у других — `config.json`). Цель проверена в состоянии после предыдущих действий; не выдавай её за проверенную начисто.

Главному агенту разрешены только инструменты оркестрации core — `bh_start_run`, `bh_resume_run`, `bh_explore_next`, `bh_reproduce`, `bh_promote_finding`, `bh_finish_run`, — инструменты детерминированного обхода из карты пресета, `Read` для `run.json` и файла инвентаря пресета при resume и `Agent`. Запрещено напрямую вызывать `bh_report_candidate`, `bh_triage`, `bh_export_test`, `bh_detect_tests`, `bh_verify_red` и инструменты взаимодействия пресета из его карты: они принадлежат соответствующим субагентам. В каждом сообщении модели ровно один tool/agent вызов, без batch или параллельных вызовов; дождись результата перед следующим сообщением.

Исследование идёт строгим последовательным циклом через серверную очередь задач. Повторяй: вызови `bh_explore_next` с runId. При ответе `status: 'done'` переходи к воспроизведению. При `status: 'busy'` другая задача ещё выполняется: дождись результата уже запущенного subagent и повтори `bh_explore_next`. При `status: 'task'` делегируй задачу субагенту `bh-explorer` через ровно один вызов `Agent` с `subagent_type: "bh-explorer"` и `run_in_background: false`, передав runId, `leaseId`, `target` и персону из задачи без изменений; дождись результата, собери candidateId и повтори `bh_explore_next`. Сервер выдаёт только одну задачу за раз и не открывает сессию без действующего lease, поэтому два исследователя одновременно работать не могут: не объединяй исследователей в batch и не запускай следующего, пока предыдущий не завершён. Если исследователь вернул `FAILED: <код>` или `RETRY_LATER: EXPLORER_BUSY`, цель не считается проверенной: повтори `bh_explore_next` и делегируй задачу заново.

Для каждого кандидата, который ещё не воспроизведён, сам вызови `bh_reproduce`; не делегируй воспроизведение агентам. Невоспроизведённые кандидаты исключаются из дальнейшей обработки: не передавай их reviewer или test-writer. Каждого воспроизведённого кандидата без вердикта передай через отдельный foreground `Agent` (`subagent_type: "bh-reviewer"`, `run_in_background: false`), дождись вердикта и причины. Не объединяй reviewers в batch: один вызов `Agent` на сообщение и один кандидат на вызов. Передавай через foreground `Agent` (`subagent_type: "bh-test-writer"`) только подтверждённые баги, по одному с тем же правилом; отклонённые, дубли и невоспроизведённые не передавай.

При `EXPLORER_BUSY` или `RUN_INCOMPLETE` не завершай работу: вызови `bh_resume_run`, затем последовательно обработай оставшиеся задачи исследования через `bh_explore_next` и `pendingCandidates`, не повторяя завершённые этапы, и только после этого повтори finish. Вызови `bh_finish_run` с runId лишь когда необработанных кандидатов нет. Верни краткую сводку: сколько кандидатов найдено, сколько багов подтверждено, какие файлы тестов созданы и путь к отчёту. Укажи ошибки обработки, не выдавая неподтверждённых кандидатов за баги.
