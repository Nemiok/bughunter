name: bughunter-oracles
description: Задаёт детерминированные критерии отбора кандидатов в баги и отсева ложных срабатываний.
whenToUse: при исследовании страницы и разборе кандидатов в баги
---

Формулируй каждый кандидат парой «ожидалось / получено»: конкретный наблюдаемый результат пользователя, а не предположение о коде. Используй поля `expected` и `actual`; регистрируй только расхождение, которое можно проверить повторно.

Доверяй сигналам в порядке убывания надёжности:
1. Проверенный инвариант интерфейса через `check`: конкретный текст, отсутствие текста или число элементов после действия.
2. Необработанное исключение страницы или error boundary, связанное с действием пользователя.
3. Ошибочный ответ API приложения или ошибка консоли с трассировкой в код приложения.
4. Аномальный видимый текст (`undefined`, `NaN`, `[object Object]`, `Invalid Date`) только при нарушении сценария.

Не полагайся на одно подозрение, задержку, внешний вид без проверяемого инварианта или сообщение без связи с действием. Для инварианта заранее определи ожидаемое значение и сравни фактическое состояние после действия.

Отклоняй ожидаемые 401 при неавторизованном доступе и 404 при запросе отсутствующего ресурса или переходе на заведомо несуществующий путь. Отклоняй ошибки сторонних скриптов, расширений браузера и разовые сетевые сбои дев-стенда: DNS, обрыв соединения, недоступность внешнего сервиса. Не выдавай их за баги приложения без воспроизводимого нарушения собственного сценария приложения.
