## 2. Что такое Bughunter

MCP stdio-сервер для доказательного поиска багов:

- **core** — доменно-нейтральный: жизненный цикл прогона, очередь и lease, кандидаты и сигнатуры,
  протокол воспроизведения, минимизация, триаж, экспорт, вердикты тестов, отчёт.
- **preset** — органы чувств домена: единица исследования, сессия, действия, снимок, детекторы,
  виды `check`, replay, генератор теста, раннер, персоны, обход, сброс, экспорт, отчёт, агенты и карта.
- Один проект = один пресет. Пресет — точка входа MCP, core подключается как `@bughunter/core`.
- Критерий: `core` не меняется ради пресета; границы закреплены тестами.

Основные документы:

- `README.md` — продукт и статус; **счётчики тестов устарели** (61/55 вместо 68/58) — docs pass.
- `.qwen/bughunter/README.md` §3–§7 — ручная установка, конфиг, запуск.
- `.qwen/bughunter/presets/node/README.md` — node-пресет.
- `docs/concept/invariants.md`, `docs/concept/preset-guide.md` — инварианты и авторство.
- `docs/superpowers/handoff/phase-b/HANDOFF.md` — предыдущая фаза; этот файл новее.

## 4. Ключевые архитектурные решения

### 4.1 Сигнатуры кандидатов

`core/src/candidate.ts`:

- один источник (только симптом или только оракул) — сигнатура байт-в-байт прежняя;
- оба источника — композит `['signal+oracle', signalSignature, oracleSignature, target]`;
- `Candidate.signalSignature` хранит сырую сигнатуру симптома;
- replay в web/node матчит `candidate.signalSignature ?? candidate.signature` — старые кандидаты
  и сигнальные кандидаты продолжают работать.

Последствие: старые `known-bugs`/`suppressions` с сырой сигнатурой один раз не дедупнутся с новым
композитным кандидатом. Это принятая цена; миграции нет.

### 4.2 Нейтральные конверты

- `Finding.subject` (бывш. `widget`), `Finding.evidenceHashes` (бывш. `responseHashes`).
- `Signal.details` (бывш. `url`/`status`).
- `StepBase.responseHashes` оставлен как поле шага — осознанно.
- Старые findings нормализуются при чтении (`legacy-envelope` маркер в `run-store.ts`).
- core-документация и core-Markdown проверяются тестом границ; `core/` не содержит `.md`.

### 4.3 verify-red

`core/src/verify-red.ts` отдаёт пресету **сырой текст** отчёта; JSON парсят сами раннеры.
Формат отчёта — знание пресета. Временный файл всё ещё называется `report.json`.

### 4.4 Qwen-плагин

- Плагин — host-адаптер: Qwen CLI, `.qwen/settings.json`, `.qwen/bughunter.json`, state в
  `.qwen/bughunter/state/<preset>`, permissions, plugin cache. Core имеет **0** упоминаний Qwen.
- Плагин объявляет MCP-сервер сам; `.mcp.json` не нужен.
- `plugins install` из локального каталога ставит плагин **disabled**; нужен `plugins enable`.
  Установка из marketplace включает плагин автоматически.
- Без `.qwen/bughunter.json` плагин **dormant**: MCP connected, 0 инструментов, состояние не создаётся.
- `${CLAUDE_PLUGIN_ROOT}` раскрывается в `mcpServers.args`; cwd MCP-сервера = корень проекта.
- Агенты и скиллы namespaced: `bughunter:bh-explorer`, `bughunter:bughunter-preset-guide` и т.п.
  Entry-скилл подставляет `<card>/<explorer>/<reviewer>/<writer>` по пресету из `.qwen/bughunter.json`.
- Node не strip-ит типы под `node_modules`; build переписывает `@bughunter/core` в относительный путь
  к `server/core/src/index.ts`. Не возвращать symlink `node_modules/@bughunter/core` — при установке
  он разворачивается в каталог и ломает запуск.
- Агенты читают state по пути плагина `.qwen/bughunter/state/<preset>/runs/`; это закреплено тестом.
- `web/src/auth.ts` пишет `storage-state.json` в state-каталог, который читает сессия, и учитывает
  `BUGHUNTER_STATE_DIR`. Старый путь `presets/state` был багом.

### 4.5 Авторство пресета

- Скиллы `bughunter-preset-guide`, `bughunter-core-contract`; шаблон CLI-пресета; бриф;
  `plugin/AUTHORING.md`.
- Один бриф = одно задание агенту, не one-shot на минуту: адаптация шаблона, фикстура, тесты,
  детерминированная приёмка. В приёмке гайдлайнов: первая итерация 0/4 из-за дефекта гайда,
  после `e81a747` — 3/4, 0 ложных, 4/4 red.
- Шаблон требует `.git` в рабочем корне (`findProjectRoot`), иначе экспорт не кладёт тест в проект.
- Документированный путь core для standalone-шаблона: `"@bughunter/core": "file:<installPath>/server/core"`
  + `npm install`. Проверено: приёмка 1/1, полный набор шаблона 35/35.

### Пересборка артефактов (если `plugin/release/` потерян)

`plugin/release/` и `plugin/dist/` игнорируются Git; после чистого клона их нет. Порядок:

```sh
node plugin/build.mjs
node plugin/test-install.mjs
mkdir -p plugin/release
(cd plugin/dist/bughunter && zip -qr ../../release/bughunter-0.1.0.zip .)
shasum -a 256 plugin/release/bughunter-0.1.0.zip > plugin/release/bughunter-0.1.0.zip.sha256

mkdir -p plugin/release/marketplace/.claude-plugin plugin/release/marketplace/plugins
cp -R plugin/dist/bughunter plugin/release/marketplace/plugins/bughunter
```

`plugin/release/marketplace/.claude-plugin/marketplace.json`:

```json
{
  "name": "bughunter-market",
  "description": "Bughunter releases: evidence-based bug hunting for Qwen Code",
  "owner": { "name": "Bughunter" },
  "plugins": [{
    "name": "bughunter",
    "description": "Bughunter MCP server, operator skills, web/node presets and the preset authoring template.",
    "version": "0.1.0",
    "source": "./plugins/bughunter",
    "author": { "name": "Bughunter" }
  }]
}
```

Затем `git init -b main` в marketplace-каталоге, коммит и проверка установки в изолированном
`--config-dir`. Новая сборка меняет SHA zip — обновить release notes.
